# SkillⅠ｜工作流字段映射

顾问填写《咨询纪要顾问确认表》，Codex 才负责将其转成冻结核心要求的内部结构。内部结构不得直接展示给顾问。

| 顾问确认表栏目 | 内部字段 |
|---|---|
| 咨询日期 | `consultation_confirmation.consultation_date` |
| 纠正的客观事实 | `corrected_facts` |
| 新增重要经历 | `newly_discovered_experience` |
| 目标地区 | `confirmed_goal_region` |
| 目标城市 | `confirmed_city_preferences` |
| 岗位偏好 | `confirmed_role_preferences` |
| 主攻方向 | `final_main_direction` |
| 相邻备选 | `final_backup_direction` |
| 平台偏好 | `confirmed_platform_preferences` |
| 明确不接受的方向 | `confirmed_exclusions` |
| 工作方式限制 | `work_style_boundaries` |
| 薪资期待 | `salary_expectation` |
| 薪资现实性专业判断 | `salary_reality_judgement` |
| 最早到岗时间 | `earliest_start_date` |
| 暂缓方向 | `directions_to_pause` |
| 定案原因 | `reasons_for_direction_decision` |
| 关键差距修复策略 | `confirmed_gap_repair_strategies` |
| 方向切换或复评标准 | `transition_reassessment_criteria` |
| 仍未确认的问题 | `unresolved_questions` |
| 下一步行动 | `agreed_actions` |
| 确认的优先行动 | `confirmed_priority_actions` |
| 顾问专业判断 | `consultant_judgement` |

## 0.3.0 咨询真相模型字段

| 顾问确认表分区 | 内部强类型字段 |
|---|---|
| 本次新增或纠正的客户事实 | `source_register.consultation_truth.customer_confirmed_facts` |
| 客户原始偏好 | `source_register.consultation_truth.customer_stated_preferences` |
| 客户可以接受的选项 | `source_register.consultation_truth.customer_accepted_options` |
| 顾问专业判断 | `source_register.consultation_truth.consultant_judgements` |
| 双方共同确认的最终决策 | `source_register.consultation_truth.jointly_agreed_decisions` |
| 顾问建议但客户尚未确认的行动 | `source_register.consultation_truth.consultant_recommended_actions` |
| 双方共同确认的优先行动 | `source_register.consultation_truth.jointly_agreed_actions` |

上述每条记录必须包含来源元数据：`source_mode`、`attribution`、`quote_status`、`verification_status`、`source_reference` 和 `evidence_limit`。顾问总结来源不得标记为客户直接原话或材料已核验。

## 0.3.0 增量合并字段

`source_register.consultation_change_log` 必须对以下字段记录 `unchanged`、`added`、`modified`、`revoked`、`superseded` 或 `unresolved`：

- target_region
- city_preferences
- role_preferences
- customer_accepted_options
- platform_preferences
- stated_exclusions
- work_style_boundaries
- customer_ideal_target
- customer_minimum_boundaries
- onboarding_timing
- identity_qualification_timing_conditions
- customer_core_decision_questions
- jointly_agreed_actions

合并后的唯一快照写入 `source_register.confirmed_consultation_snapshot`，最终报告只读取该快照和既有事实真源，不得从未确认顾问总结或逐字稿自由投影。

## 映射边界

1. 新增重要经历必须保留“已确认的结果或状态”与“仍未确认的数据”的区分，并标记为咨询确认来源。
2. 内部初始确认状态为 `draft`；顾问明确确认后才变为 `confirmed`。
3. 该映射不得修改冻结核心字段含义。
4. `confirmed_exclusions` 不能自动映射为 `directions_to_pause`。
5. 顾问判断不能自动映射为客户确认事实。
6. `unresolved_questions` 只保留仍会影响最终方向、资格、窗口或行动选择的问题。
7. `agreed_actions` 只记录咨询中达成一致的行动意图；最终行动清单仍须以最终报告为依据生成。
8. `confirmed_gap_repair_strategies` 和 `confirmed_priority_actions` 各最多 3 项，不得为了凑数生成。
9. 顾问没有形成明确判断时，内部字段保留“未形成明确判断”，最终报告必须保留证据边界，不得强行定案。
10. 没有外部市场样本时，`external_market_reference_used` 必须为 `false`，最终 JSON 的 `external_market_reference.status` 必须为 `not_used`。
11. 每条 `unresolved_questions` 必须包含 `source_reference`、`why_decision_relevant` 和 `unresolved_reason_type`；展示层未确认项必须从同一结构化集合投影，不得凭平台规模偏好扩展行业偏好补问。
