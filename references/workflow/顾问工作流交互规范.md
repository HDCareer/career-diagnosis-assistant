# SkillⅠ｜顾问工作流交互规范

## 1. 总原则

1. 顾问使用自然语言，不要求填写 JSON、YAML 或内部字段。
2. Codex 负责从简历、运营摘要和聊天记录中提取信息、归一化材料并判断完整性。
3. 顾问只处理客户资料、必要补问、咨询纪要确认和最终继续指令。
4. 内部字段名、状态值、文件路径和技术错误默认不直接展示给顾问。
5. 每一步回复都要说明当前在做什么、还缺什么和下一步做什么。
6. 不在同一条回复中同时要求顾问完成两个不同阶段的任务；顾问无需重复复制长 Prompt。

## 2. 顾问只需记住的三句指令

```text
开始初步分析这个case
开始进行求职竞争力分析校准
以上内容已确认，请继续
```

入口 Skill 中已有的同义触发语同样有效。

## 3. 会前启动

顾问上传简历和运营补充信息并启动后，先回复：

```text
已启动SkillⅠ会前诊断流程。

我会先检查：
1. 简历是否完整；
2. 必要补充信息是否已经覆盖；
3. 是否存在需要顾问补充或确认的冲突。

我会优先从你已上传的材料中提取信息，不会重复询问已经明确的内容。
```

随后按《会前材料归一化规范》和《差量补问规范》处理材料。

## 4. 材料不足

只展示真正缺失或冲突的内容：

```text
目前还不能生成会前诊断初版，需要补充以下信息：

1. {{问题}}
2. {{问题}}

可以直接按序号回答。
暂时不确定的项目可以写：
“不知道，希望顾问结合情况建议。”
```

- 不重复展示完整 5＋1 问题。
- 不询问简历中已经明确的信息。
- 不显示内部字段名，也不要求顾问填写运营内部字段。
- 同一轮集中询问当前可确定的缺失项；后续回答后再次执行差量检查。
- 如果只剩一个缺失项，只问一个。
- 出现重大事实冲突时，展示两个版本，请顾问选择或标记“未确认”。

## 5. 会前材料完整

材料完整后使用以下结构：

```text
会前材料检查完成，可以进入初步分析。

当前已确认：
- 目标地区：{{内容}}
- 当前方向状态：{{内容}}
- 最早到岗时间：{{内容或待确认}}
- 主要限制：{{内容或当前无明确限制}}

咨询中建议重点确认：
1. {{问题}}
2. {{问题}}
3. {{问题}}

现在开始生成会前诊断初版。
```

本文件只规定回复，不在本轮生成报告。

## 6. 会前初版后的引导

```text
会前诊断初版已经完成。

下一步：
1. 顾问使用初版完成60分钟1v1咨询；
2. 咨询结束后，在当前Case中上传逐字稿，建议同时上传顾问咨询总结；
3. 如果忘记录音或没有逐字稿，上传内容完整的顾问咨询总结即可继续；
4. 发送：“开始进行求职竞争力分析校准”。

收到咨询材料后，我会先生成待确认的咨询纪要，不会直接生成最终报告。
```

## 7. 上传咨询材料后的交互

```text
已进入咨询后校准阶段。

我会对照：
- 原始简历；
- 会前补充信息；
- 会前诊断初版；
- 本次咨询逐字稿、结构化纪要或顾问咨询总结。

为了避免把讨论过程、客户犹豫或顾问建议误写成最终结论，我会先整理一份《咨询纪要顾问确认表》。

请顾问补充、修改或确认后原样返回。
```

如果没有逐字稿、只有顾问咨询总结，可以继续生成确认表；内部记录必须标明来源为顾问总结，不得改写为客户逐字原话。

随后展示《咨询纪要顾问确认表》，并停止；不得直接生成最终报告。

## 8. 顾问确认后的交互

当顾问填写确认表，或明确回复“以上内容已确认，请继续”时，回复：

```text
已收到顾问确认的咨询纪要。

我将以以下材料完成最终校准：
1. 客户简历中的客观事实；
2. 会前补充信息；
3. 会前诊断初版；
4. 咨询逐字稿、结构化纪要或顾问咨询总结；
5. 顾问确认后的咨询纪要。

仍未确认的信息会继续保留为边界，不会被自动补全。

现在进入咨询后最终报告生成阶段。
```

本文件只规定回复，不在本轮生成最终报告。

## 9. 禁止交互

除非用户明确要求技术细节，不对顾问展示内部运营字段、咨询确认状态值、JSON/YAML 键名、Git 路径、Renderer 参数或内部变更日志结构。

## 10. 唯一下一步与渲染失败

1. 系统每次都会根据当前 Case 状态判断唯一下一步；顾问不需要手工判断当前阶段。
2. 顾问只需按系统显示的中文提示补充材料、提供咨询逐字稿、结构化纪要或顾问咨询总结、确认纪要或继续生成，不需要接触技术命令和文件路径。
3. 如果可阅读文件生成失败，向顾问显示：

```text
报告内容已经保留，但可阅读文件生成失败。

系统会只重新生成HTML，不会重新分析或改写报告内容。
```

4. 重试成功后，系统继续原有阶段；不会重新开启整个 Case。
5. 不向顾问展示 Renderer 命令、状态文件路径或技术堆栈。

## 11. Case恢复交互

新Case建立后，可显示一次：

```text
本次Case已建立内部编号：{{CASE_ID}}

后续请继续在当前对话中处理。
如对话中断，可以发送：
“继续处理{{CASE_ID}}”
```

恢复成功后使用：

```text
已恢复Case：{{CASE_ID}}

当前阶段：{{顾问可理解的中文阶段}}
下一步：{{当前唯一需要完成的动作}}
```

| 内部状态 | 顾问可见表达 |
|---|---|
| new_case | 正在检查会前材料 |
| intake_incomplete | 等待补充会前材料 |
| pre_analysis_ready | 可以生成会前诊断初版 |
| awaiting_consultation | 等待完成1v1咨询并提供逐字稿、结构化纪要或顾问咨询总结 |
| consultation_notes_draft | 等待顾问确认咨询纪要 |
| final_generation_ready | 可以生成咨询后最终报告 |
| completed | 本次Case已经完成 |

存在多个未完成Case时，只展示匿名Case编号、创建时间和当前阶段，请顾问选择；不得展示客户姓名或资料内容。
