# SkillⅠ v3.0 / 0.3.0｜测试样例

## 使用目标

本文件用于验证两阶段诊断流程，避免把会前初版误作正式最终报告、用咨询内容覆盖未经确认的事实，或让行动清单脱离最终报告生成。

测试只验证规则，不执行联网、岗位爬取、逐 Case 市场调研、销售判断或新章节扩展。Renderer 使用当前正式入口验证最终 HTML 和行动清单兼容性。

## 通用验收点

每次修改后至少检查：

1. 会前输入齐全时只生成 `pre_consultation_report_data.json` 和 `pre_consultation_report.md`，且 `consultation_confirmation_status: not_started`。
2. 会前报告显示“会前诊断初版｜供1v1咨询讨论使用”，不称最终定案，不生成行动清单。
3. 最终阶段必须具备初版、完整简历、归一化会前材料、至少一种咨询材料、归一化咨询纪要、`consultation_confirmation_status: confirmed`、`confirmed_consultation_snapshot` 和明确标注的剩余未知。
4. 逐字稿、结构化纪要或顾问总结只能将 `not_started` 改为 `consultation_confirmation_status: draft` 并生成确认模板后停止；`not_started` 和 `draft` 都不得生成最终报告、行动清单、内部变更记录或最终 HTML。
5. 最终阶段生成最终报告、行动清单和内部变更记录；行动清单的客户内容只基于最终报告。
6. `operating_notes` 字段必须存在但可全部为空，不得阻塞会前初版。
7. 客户报告为封面＋9章，旧版独立“目标达成概率”章节不存在。
8. 三维对标使用基础资本与准入条件、岗位匹配与经历支撑、求职准备与执行成熟度，并含 1—5 级双线数据。
9. 三维目标要求不能宣称来自成功录用统计、实时市场数据或精确概率。
10. 方向类别为主攻、相邻备选、稳妥推进、条件探索、诊断性暂不建议；后者可为空。
11. 客户主动排除方向只进入 `stated_exclusions`，不得重写为诊断性暂不建议。
12. 04、05、06、07 遵守章节所有权，不完整重复经历、数字、差距或推荐理由。
13. 客户正文使用“你”，不暴露匿名编号、联系方式、JSON/YAML 键名、内部流程或销售黑话。
14. 默认不联网、不生成岗位清单、实时岗位链接、市场校准或渠道评估。
15. 不承诺 Offer、内推、录用、薪资、签证、身份、移民或渠道结果。
16. 海外路径按 `overseas_sales_boundary.md` 显示身份和工作权利边界，不把它们写成保障。

## V3.0 / 0.3.0 回归测试矩阵

### RT-01：咨询后修改主方向

**输入**：会前初版主攻为“内容运营”；咨询中客户明确确认更想做且经历更匹配“用户运营”。

**预期**：最终报告将主攻更新为“用户运营”；01、03、05、06、07、08、09 同步一致；变更记录写明方向变化原因；会前初版仍保留原始版本，不被覆盖。

### RT-02：咨询后补充简历未写经历

**输入**：客户在咨询中确认一段简历未写的跨部门活动复盘经历，且确认了交付物，但未确认具体影响范围。

**预期**：最终报告可在 04 章使用该经历，并标注来源于咨询确认；07 章只做能力映射；不得虚构影响范围或量化结果；变更记录归入 `newly_added_information`。

### RT-03：客户主动排除销售岗位

**输入**：客户在咨询中明确表示不接受销售岗位及强销售 KPI。

**预期**：最终报告在第 02 章 `stated_exclusions` 记录该边界；销售不得再次出现在 `diagnostic_not_recommended`；行动清单不包含销售验证或准备动作。

### RT-04：无合理暂不建议方向

**输入**：当前所有已讨论方向要么是主攻/备选/条件探索，要么客户没有提出冲突方向。

**预期**：`direction_decision.diagnostic_not_recommended` 允许为空；客户报告不为了凑结构编造暂不建议方向。

### RT-05：售前与咨询信息冲突但未确认

**输入**：售前称“可接受异地”，咨询记录中出现“可能不太接受”，但客户没有明确最终选择。

**预期**：最终报告不得以咨询中的模糊表述覆盖原信息；该事项继续列为未确认边界；不得把它伪装为客户已确认的限制。

### RT-06：已确认信息不得残留为待确认

**输入**：会前初版将“最早到岗时间”列为咨询中需要确认；咨询中客户明确确认 2026 年 7 月可到岗。

**预期**：最终报告的第 02、08、09 采用已确认日期；待确认列表中不再出现该项；变更记录归入 `resolved_unknowns`。

### RT-07：三维对标不得伪装成录用统计

**输入**：会前或最终报告生成三维对标。

**预期**：每一维都有 `candidate_level`、`target_entry_level`、判断、依据、差距、优先动作和置信说明；正文明确为常见入门要求，不含“成功录用人群”“百分位”“平均分”“成功率”或精确概率。

### RT-08：04、05、06、07 去重

**输入**：某段经历含具体项目数据，同时支撑优势、差距判断和主方向准备。

**预期**：04 章完整呈现经历与数据；05 章只讲差距及改善；06 章只用方向理由摘要；07 章只用经历名称、能力映射和使用场景。不得完整重复经历或同一推荐理由。

### RT-09：最终行动清单字段完整

**输入**：咨询后最终报告已经确定主攻、边界、重新评估信号，并在最终 JSON 中写入 `recruitment_path_salary_and_roadmap.priority_action_scaffolds`。

**预期**：新生成最终报告必须包含 0—3 项 `priority_action_scaffolds`，不得为了凑数强行生成。每项必须包含 `action_name`、`why_now`、`dependency`、`first_15_minute_step`、`content_framework`、`minimum_viable_output`、`estimated_effort`、`completion_check` 和 `common_mistakes`。行动清单必须由物化器从最终 JSON 生成；旧五列表只用于旧 V3 历史兼容，不作为 0.3.0 新生成清单格式。

### RT-10：会前初版不得误标最终报告

**输入**：仅有完整简历、5+1 回答和运营补充信息，尚未咨询。

**预期**：只输出会前文件，封面与第 01 章使用初版标识和初步判断；所有待确认信息明确显示；不得输出 `final_customer_report.*`、行动清单或“咨询后最终版”标识。

### RT-11：只有逐字稿，未经过顾问确认

**输入**：会前初版、完整简历、60 分钟逐字稿；没有顾问确认纪要。

**预期**：生成完整待确认咨询纪要模板，`consultation_confirmation_status: draft`；显示“当前咨询纪要仍处于待确认状态”的固定提示后停止；不生成最终报告、行动清单或变更日志。

### RT-12：顾问确认后生成最终报告

**输入**：RT-11 生成的咨询纪要模板，顾问已修改或明确回复“以上咨询纪要已确认”，状态为 `confirmed`。

**预期**：可以生成最终报告、行动清单和变更日志；最终报告只采用已确认内容；逐字稿中的犹豫、试探性表达和顾问建议不得自动变成客户事实。

### RT-13：运营没有额外补充

**输入**：完整简历、5 个固定问题、1 个地区动态问题；`operating_notes` 存在但五个标准字段全部为空，或填写“无额外补充”。

**预期**：输入校验通过，正常生成会前诊断初版；不得要求运营虚构额外信息。

### RT-14：行动清单不能绕过最终报告

**输入**：咨询纪要中讨论过一项方向，但最终报告未采纳；最终报告已完成且数据与正文一致。

**预期**：行动清单不得出现该方向；只提炼最终报告中的主攻、备选、剩余边界、行动路线和重新评估信号。

### RT-15：文件与版本一致性

**输入**：当前生产规范文件。

**预期**：当前生产规范中没有错误的旧版版本号表述；不存在旧名称与新名称两份重复行动清单规范；所有相对路径和读取规则有效。

### RT-16：会前初版状态

**输入**：完整简历、5 个固定问题、1 个地区动态问题、有效 `operating_notes`；尚无咨询逐字稿。

**预期**：正常生成会前初版；`consultation_confirmation_status: not_started`；不得使用 `draft` 或 `confirmed`；不生成最终报告或行动清单。

### RT-17：状态流转

**输入**：依次提供完整会前材料、咨询逐字稿、顾问确认纪要。

**预期**：状态依次为 `not_started → draft → confirmed`，任一步不得跳过。

### RT-18：错误状态拦截

**输入**：分别以 `not_started` 请求生成最终报告、以 `draft` 请求生成最终报告、以及 `confirmed` 但缺少会前初版或完整简历。

**预期**：前两种必须停止；第三种也必须停止并指出缺失材料；不得因为状态为 `confirmed` 就忽略其他最终报告触发条件。

### RT-19：客户首选A、接受B、顾问建议B

**输入**：客户首选方向A，表示可以接受方向B；顾问建议B为主攻，但没有客户共同定案。

**预期**：`customer_stated_preferences` 记录A；`customer_accepted_options` 记录B；`consultant_judgements` 记录顾问建议B；不得自动生成 `jointly_agreed_decisions = B`。

### RT-20：客户明确接受顾问建议并共同定案B

**输入**：客户明确同意顾问建议B为最终主攻，并在确认表中形成一致依据。

**预期**：只有此时才允许 `jointly_agreed_decisions = B`，且必须包含明确一致依据。

### RT-21：只有顾问总结的降级来源

**输入**：没有逐字稿，只有内容完整的顾问总结，顾问总结称“客户接受B”。

**预期**：可以生成确认草稿；来源标记为顾问总结，`verification_status` 可为 `consultant_recorded`；不得标记客户直接原话或材料已核验。

### RT-22：会前边界未提及必须保留

**输入**：会前排除外包、央国企，咨询未提及。

**预期**：合并快照继续保留两个排除项；`consultation_change_log` 记录 `unchanged`，最终报告不静默删除。

### RT-23：咨询明确撤销会前边界

**输入**：咨询明确撤销“排除央国企”。

**预期**：合并快照不再保留该排除项；`consultation_change_log` 记录 `revoked`；最终客户报告不得回流已撤销旧值。

### RT-24：咨询修改城市优先级

**输入**：会前深圳优先，咨询改为广州优先。

**预期**：变更记录为 `modified`，保留旧值、新值和来源；最终报告只使用新顺序。

### RT-25：无来源待确认问题失败

**输入**：客户未提家庭、预算或语言，且不属于方向硬性条件。

**预期**：不得自动生成相应待确认问题；若生成，validator 必须失败。

### RT-26：香港就业路径工作权利问题

**输入**：香港就业路径需要确认工作权利。

**预期**：可生成待确认问题，但必须带 `source_reference` 和 `why_decision_relevant`。

### RT-27：招聘阶段不得泄漏内部流程

**输入**：最终报告的 `candidate_recruitment_stage` 被写成“等待顾问确认”。

**预期**：validator 失败；客户报告只能展示真实招聘阶段。

### RT-28：Case 存储在仓库外

**输入**：默认初始化 Case，或显式把 Case 根目录设为仓库内路径。

**预期**：默认路径在操作系统用户数据目录；生产模式拒绝仓库内路径；运行合成 Case 后 Git 状态不因运行数据变化。

## 0.3.0 内容契约回归

### CCT-01：最多 3 个核心问题被逐项回答

**输入**：最终报告包含 1—3 个 `decision_snapshot.core_question_answers`。

**预期**：每项包含问题、回答、回答状态和边界；超过 3 项必须失败；已完成咨询后能回答的问题不得简单推回“后续咨询顾问”。

### CCT-02：自述和顾问总结不能升级成已核实

**输入**：客户自述、咨询自述、顾问总结或顾问判断出现在 `source_register.critical_evidence_status`。

**预期**：这些来源不能写成 `material_verified` 或 `independent_verified`；客户正文不得出现“已核实”“已验证”等验证性措辞。

### CCT-03：当前资产、未来潜力和计划事项分开

**输入**：客户尚未入学、计划考证、计划实习、计划作品或计划补充材料。

**预期**：不得进入 `candidate_context.current_assets`；只能进入 `future_potential` 或 `planned_not_current`，并保留尚未形成当前竞争力资产的边界。

### CCT-04：无外部样本时不生成市场薪资数字

**输入**：`salary_assessment.external_market_reference.status: not_used`。

**预期**：不得输出市场薪资区间、岗位薪资数字或伪市场参考；可以保留顾问对客户薪资目标的定性现实判断。

### CCT-05：客户薪资期待不能当成市场参考

**输入**：客户表达理想薪资或最低薪资边界，但未提供外部市场样本。

**预期**：客户期待只能进入 `customer_ideal_target` 或 `customer_minimum_boundaries`；不得填入 `external_market_reference`。

### CCT-06：薪资现实性判断五档有效

**输入**：顾问对薪资目标做出 `realistic`、`challenging`、`stretch`、`currently_unrealistic` 或 `insufficient_basis` 判断。

**预期**：五档均为合法枚举；顾问未形成明确判断时使用 `insufficient_basis` 并在证据边界中说明。

### CCT-07：高优先级问题形成修复卡

**输入**：最终版存在高优先级差距或顾问确认的差距修复策略。

**预期**：最多 3 项进入 `improvement_priorities`，并形成修复卡字段：招聘方顾虑、处理原则、简历策略、面试框架、需准备证据、避免措辞、剩余风险和重新评估条件。

### CCT-08：新行动清单使用脚手架结构

**输入**：最终 JSON 含 0—3 项 `priority_action_scaffolds`。

**预期**：有行动时每项必须具备 9 个脚手架字段；无行动时保留空数组并物化为“当前无需要脚手架化的高难度行动”；不得回退为新生成五列表。

### CCT-09：JSON 确定性物化 Markdown 和行动清单

**输入**：合法 `final_customer_report_data.json`。

**预期**：当前运行模式的 `content_materializer.py` 确定性生成 `final_customer_report.md` 和 `post_consultation_action_checklist.md`；repository 模式使用 `workflow/content_materializer.py`，Plugin 模式使用 `scripts/content_materializer.py`。行动清单只从最终 JSON 提炼。

### CCT-10：重复物化结果字节一致

**输入**：同一份最终 JSON 连续物化两次。

**预期**：报告 Markdown 和行动清单 Markdown 字节完全一致，不受运行时间、文件顺序或非确定性遍历影响。

### CCT-11：旧 V3 fixture 仍可兼容渲染

**输入**：旧 V3 fixture 没有 `priority_action_scaffolds`，但提供历史 3—5 项五列表行动清单。

**预期**：Renderer 仍可作为历史兼容路径渲染；该兼容路径不得成为 0.3.0 新生成行动清单格式。

## 0.3.1 内容契约回归

### CCT-12：明确截止日早于 30 天时优先使用明确日期

**输入**：`report_date=2026-06-28`，`explicit_deadline=2026-07-15`，第一阶段写成“30天内完成是否接受录取的路径决策”。

**预期**：Validator 失败。第一阶段标题、目标、行动、产出和完成标志必须使用“2026年7月15日前”或“关键截止日前”；60 天和 90 天阶段只能写成决策后的分支执行、后续验证或路径推进。

### CCT-13：待确认问题必须有来源和决策必要性

**输入**：`source_register.unresolved_questions` 缺少 `source_reference`、缺少 `why_decision_relevant`，或只写“有助于进一步了解客户”。

**预期**：Validator 失败。合法项必须包含 `question`、`source_reference`、`why_decision_relevant` 和 `unresolved_reason_type`，且 `unresolved_reason_type` 只允许 `explicit_missing`、`conflict`、`required_qualification`、`region_required`。

### CCT-14：平台规模偏好不得扩展为行业偏好补问

**输入**：客户只表达“优先成熟科技公司和业务稳定的中型互联网公司”。

**预期**：不得生成“需要收窄行业偏好”。若报告或行动清单展示该问题，必须因缺少结构化来源而校验失败。

### CCT-15：合法证据口径和工作权利问题仍可保留

**输入**：量化成果缺少原始报表和计算口径；香港就业路径涉及工作权利。

**预期**：前者可登记为 `explicit_missing`，后者可登记为 `required_qualification` 或 `region_required`；两者都必须带来源和决策相关原因。

## 基础场景回归

| 场景 | 输入状态 | 预期 |
|---|---|---|
| 完整材料的中国内地求职 | 完整简历＋5+1＋运营补充 | 会前初版；判断中国内地窗口，使用方向级建议而非实时岗位 |
| 香港/大湾区双路径 | 完整会前材料 | 会前初版使用路径卡片；身份仅作窗口信息，不作结果保障 |
| 澳洲或美国本地求职 | 完整会前材料 | 会前初版列出工作权利/签证待确认；遵守对应海外边界 |
| 多路径比较 | 完整会前材料 | 使用路径卡片和主/次/备选/暂不优先总结，不用宽表 |
| 只有简历截图 | 残缺材料 | 不生成任何报告；请求完整简历，可给低置信度宽泛启发 |
