# SkillⅠ v3.0｜报告输出规范

## 1. 使用目标

本文件规定 SkillⅠ v3.0 的会前诊断初版、咨询后最终报告和结构化数据输出标准。

默认报告名称均为《个人求职竞争力与方向决策报告》，但必须按阶段显示：

| 阶段 | 客户显示标识 | 交付定位 |
|---|---|---|
| `pre_consultation` | 会前诊断初版｜供1v1咨询讨论使用 | 方向假设、信息缺口、咨询议程 |
| `post_consultation_final` | 咨询后最终版｜依据简历、补充信息及1v1咨询确认 | 正式客户报告、行动清单的唯一依据 |

国内院校且中国内地求职使用“求职竞争力与方向诊断服务”；海外院校回国、香港、澳洲、美国或包含海外路径的多路径 case 可使用“留学生求职竞争力与方向诊断服务”。不得错误添加身份描述。

默认不输出市场校准、岗位样本、渠道评估、Deep Research 建议、销售话术或 SkillⅡ 训练稿。

0.3.0 起，V3 JSON 是唯一专业内容真源。正常 Case 中 Codex 只生成会前/最终 JSON、内部 `confirmed_consultation_snapshot` 和 `consultation_change_log.md`；报告 Markdown 与行动清单 Markdown 由当前运行模式的 `content_materializer.py` 从 JSON 确定性生成，再由 Renderer 输出 HTML。repository 模式使用 `workflow/content_materializer.py`，Plugin 模式使用 `scripts/content_materializer.py`。

## 2. 两阶段输出与文件命名

### 会前诊断初版

只在完整简历、5 个固定问题、1 个地区动态问题和 `operating_notes` 字段齐全时生成。`operating_notes` 内容允许为空；空数组、标准空值或“无额外补充”均为有效输入，只有字段完全缺失时才提醒运营确认：

```text
pre_consultation_report_data.json
pre_consultation_report.md
```

其中 `pre_consultation_report.md` 由确定性代码从 `pre_consultation_report_data.json` 物化生成，Codex 不重复手写完整 Markdown。

初版必须：

1. 将方向、窗口、薪资和行动表达为当前信息下的初步判断。
2. 将影响判断的未知信息明确列为“咨询中需要确认”。
3. 不称为最终定案，不输出 `post_consultation_action_checklist.md`。
4. 不因未知项虚构答案，不联网，不生成具体岗位清单或实时岗位链接。
5. 在 `pre_consultation_report_data.json` 中固定写入 `consultation_confirmation_status: not_started`。

### 咨询后最终报告

只有同时具备已有初版、完整简历、归一化会前材料、至少一种原始咨询材料、已归一化的咨询纪要、`confirmed_consultation_snapshot`，且 `consultation_confirmation_status: confirmed` 时生成：

```text
final_customer_report_data.json
final_customer_report.md
post_consultation_action_checklist.md
consultation_change_log.md
```

其中 `final_customer_report.md` 和 `post_consultation_action_checklist.md` 由确定性代码从 `final_customer_report_data.json` 物化生成；Codex 只保留生成内部 `consultation_change_log.md`。行动清单必须来自 `recruitment_path_salary_and_roadmap.priority_action_scaffolds`，不得从逐字稿或变更记录另行新增行动。

逐字稿、顾问记录或初步纪要必须先归一化为 `consultation_confirmation_status: draft` 的完整确认模板，并在输出模板后停止。`draft` 状态不得生成本节的任一文件，必须固定提示：

> 当前咨询纪要仍处于待确认状态。请顾问完成补充、修正或明确确认后，再生成咨询后最终报告。

最终报告必须优先使用 `confirmed_consultation_snapshot` 和既有事实真源，但不得覆盖未被客户明确纠正的简历客观事实。`consultation_change_log.md` 是内部文件，不得写入客户报告。

### 咨询后行动清单依据

生成咨询后行动清单前，必须确认最终报告数据、最终报告正文、已确认的咨询纪要、已确认合并快照和内部变更记录均已存在。

行动清单的客户内容只允许从 `final_customer_report_data.json` 和与其一致的 `final_customer_report.md` 中提炼。已确认咨询纪要和 `consultation_change_log.md` 只用于一致性校验、确认信息来源和防止遗漏，不得绕过最终报告直接新增行动、方向或结论。

如果最终 JSON 与最终 Markdown 不一致，必须先修正最终报告，不能直接生成行动清单。行动清单不得根据逐字稿增加最终报告未采纳的方向，不得根据变更记录恢复已删除或否定的会前方向；其中的剩余未知、主攻、相邻备选、行动路线和重新评估信号必须与最终报告一致。

## 3. 客户报告结构：封面＋9章

不得输出旧版“封面＋10章”结构，也不得保留独立“当前目标达成概率拆解”章节。

| 章节 | 标题与固定内容 |
|---|---|
| 封面 | 阶段标识、姓名、报告名称、目标地区/路径、日期和中性核心判断；不展示匿名编号、联系方式或问题清单 |
| 01 | 会前为“会前诊断总览”，最终为“咨询后结论总览”；先展示一页版客户决策摘要，再包括核心判断、核心诉求、主攻、相邻备选、最多 3 个核心问题回答、3 项优势、3 项差距、3 个动作 |
| 02 | 求职画像与决策边界：背景摘要、地区/城市/时间、岗位诉求、平台偏好、工作方式、确认限制、客户主动排除方向、尚未明确问题 |
| 03 | 三维竞争力对标：基础资本与准入条件、岗位匹配与经历支撑、求职准备与执行成熟度 |
| 04 | 核心优势与判断依据：默认 3 项优势、经历依据、求职价值和适用场景 |
| 05 | 关键差距与提升优先级：会前可列初步风险；最终最多 3 项修复卡，含招聘方顾虑、处理原则、简历策略、面试框架、证据、禁用措辞、剩余风险和复评条件 |
| 06 | 求职方向决策：先展示方向决策矩阵，再展示主攻、相邻备选、稳妥推进、条件探索、诊断性暂不建议；方向卡可显示可用证据、主要障碍和长期路径价值 |
| 07 | 主方向准备方案：岗位名称、工作内容、能力、可用经历、待补内容、简历重点、3 个面试故事、调整信号 |
| 08 | 招聘路径、薪资与行动路线：阶段、窗口、优先/同步路径、特殊渠道、节点、薪资分层、可选市场参考、决策建议、30/60/90 天路线和优先行动脚手架 |
| 09 | 信息依据与报告边界：资料来源、咨询确认来源、剩余未知、关键证据可信度分层、资格/薪资/市场边界和适用范围 |

## 4. 章节内容规则

### 01 核心结论

在 30 秒内读完。先输出“一页版客户决策摘要”，让客户能快速看到当前建议、主攻方向、为什么不是其他方向、最该做的 3 件事、仍不能确定的 3 件事和重新判断信号。每个模块最多 3 项。只做摘要，不完整复述经历、数字或建议理由。

1. 核心判断不超过 100 个中文字符。
2. 主攻方向必须有一句理由；相邻备选必须有一句启用条件。
3. 三项优势和三项差距只写摘要，不重复 04、05 的完整内容。
4. 三个动作写成“动作＋预期产出”。
5. 会前版必须使用“初步判断”“待咨询确认”等合适表达；最终版不得保留已解决的待确认事项。
6. 最终版必须使用 `decision_snapshot.core_question_answers` 逐项回答客户最核心问题，最多 3 项；不能只保留 `core_request`。

### 02 求职画像与决策边界

只展示影响决策的事实，不重述完整简历。岗位诉求、平台偏好、招聘路径和工作方式必须拆开。

`stated_exclusions` 只记录客户明确排除的方向或条件，只在本章展示。长期海外目标仅在身份、长期居留或海外经验目标影响路径判断时单列，否则合并到地区说明。

### 03 三维竞争力对标

每一维必须使用：

```yaml
dimension_name:
candidate_level: 1-5
target_entry_level: 1-5
current_judgement:
basis:
main_gap:
priority_action:
confidence_note:
```

`candidate_level` 和 `target_entry_level` 均为规则化的 1—5 级标尺。`target_entry_level` 仅表示目标岗位常见入门要求，不是历史录用统计、实时市场数据或精确录用概率。不得出现均分、百分位、成功率、百分比概率、S/A/B/C/D、B+ 或 A-。

招聘阶段、招聘窗口和达成状态的必要解释并入本章或第 08 章，不能另设旧版概率章节。无实时信息时只能写“关注并核实”，不得断言具体招聘批次正在开放。

### 04 核心优势与判断依据

默认 3 项，特殊 case 最多 4 项。每项使用“核心优势、经历依据、求职价值、适用场景”。优势必须是能力组合，不能只写学校、经历丰富或沟通能力强。客户正文使用“经历依据”“判断依据”“可用经历”“尚需补充的信息”“可验证结果”，不机械显示“证据”。

目标相关的学生干部、荣誉、志愿服务、组织协调、文书材料和项目经历可作为内部 `target_relevant_evidence`，但不能成为独立客户章节。已有证据不得误写为缺失。

### 05 关键差距与提升优先级

每项固定包含：

1. 关键差距。
2. 为什么影响当前目标。
3. 当前程度或问题类型。
4. 具体改善方式。
5. 改善后能够解决什么。
6. 优先级（高/中/低）。

问题类型仅可使用：硬门槛、材料表达问题、短期可训练问题、需要长期积累的问题、信息确认/决策边界问题。城市、轮岗、销售、合同制、薪资底线、Sponsor 等未知边界不得误归为短期可训练问题。

最终版最多深挖 3 项，并必须扩展为修复方案卡，额外包含：

```yaml
recruiter_concern:
handling_principle:
resume_strategy:
interview_framework:
evidence_to_prepare:
wording_to_avoid:
residual_risk:
reassessment_condition:
```

统一原则：重构表达，不重构事实；提升叙事，不制造经历。不得鼓励虚构、隐瞒或把未来能力写成已有能力。

### 06 求职方向决策

方向数量：主攻必须 1 个；相邻备选 0—1 个；稳妥推进 0—1 个；条件探索 0—2 个；诊断性暂不建议 0—2 个，可以为空。

`diagnostic_not_recommended` 必须来自独立专业判断，含独立原因和重新评估条件。它与 `stated_exclusions` 相互排斥：客户明确拒绝的方向不得再作为诊断性暂不建议方向，且不得为凑数量生成暂不建议。

主攻方向必须是一个较窄岗位族，最多容纳 2—3 个高度相似岗位名称，能共享简历重点、能力模型和面试故事。相邻备选必须有可迁移证据和启用条件。稳妥推进仅在核心门槛基本满足时成立；核心资格待核实的方向应进入条件探索。条件探索必须写清当前为什么不是优先、满足什么条件后可以尝试及低成本验证方式。

方向对象可按适用情况增加：

```yaml
usable_evidence:
main_barrier:
long_term_path_value:
```

不得新增第二套方向体系；Renderer 必须在第 06 章先基于现有方向分类轻量展示方向决策矩阵，再展示方向卡片。矩阵只做横向比较，不新增结论。

### 07 主方向准备方案

只围绕一个主攻方向。固定包含：常见岗位名称、主要工作内容、通常看重的能力、当前可用经历、需要补充内容、简历表达重点、3 个优先面试故事和方向调整信号。优先面试故事必须说明使用场景；如结果边界或证据暂未确认，必须直接写明。

本章只用经历名称、能力映射和使用场景，不得重复 04 章完整数字、成果、奖项或职责。STAR 中的结果必须是真实结果；没有确认结果时写“结果证据暂未确认”，并记录需要补充的内容，不得把生成原则当成结果。

### 08 招聘路径、薪资与行动路线

固定整合：客户真实招聘阶段、当前窗口判断、优先招聘路径、可同步关注路径、特殊招聘渠道、下一关键节点、薪资参考和 30/60/90 天路线。

`candidate_recruitment_stage` 只描述客户真实招聘阶段，例如毕业前求职准备期、秋招准备期、春招补录期、日常实习期、毕业后社招期、转行准备期或 Offer 比较期。客户报告中不得出现会前诊断阶段、等待咨询、咨询纪要草稿、等待顾问确认、最终生成阶段等内部工作流词。

客户提供的招聘路径偏好只有在构成真实硬性限制时才进入第 02 章；顾问建议的招聘路径必须放在本章。可以给单位官网、学校/机构官网、公共招聘平台、行业协会、NGO/国际组织官网、校园就业中心、Graduate Program 等方向级渠道建议，但不得生成实时岗位链接或伪装为正在招聘。

薪资以 `salary_assessment` 为正式来源。必须区分客户理想目标、客户最低边界、顾问现实性判断、可选外部市场参考、决策建议和证据边界：

```yaml
salary_assessment:
  customer_ideal_target:
  customer_minimum_boundaries:
  consultant_reality_label: realistic | challenging | stretch | currently_unrealistic | insufficient_basis
  consultant_reasoning:
  external_market_reference:
    status: not_used | provided
  decision_guidance:
  evidence_limit:
```

`external_market_reference.status: not_used` 时，不得输出伪市场数字，不得把客户期待写成市场参考，仍需给出顾问对目标的定性现实判断。只有 `provided` 时才能出现具体市场数字，并必须有地区、岗位、口径、时间、来源类型和置信度。旧 `salary_reference` 只作兼容读取，新生成最终报告以 `salary_assessment` 为正式来源。

行动脚手架存入 `priority_action_scaffolds`，最终版为 0—3 项，按依赖顺序排列，默认顺序为事实和证据核实、目标岗位能力要求、简历重构、作品或材料补强、投递验证。第 08 章必须同步展示优先行动脚手架，行动清单再作为客户执行版单独输出。不得为了凑数强行生成 3 项。

30/60/90 天每一阶段都必须有阶段目标、核心行动、本阶段产出和完成标志。不能写购买服务、报名、选择陪跑或联系顾问作为核心行动或完成标志。

### 09 信息依据与报告边界

只保留：资料来源、咨询确认来源、剩余未确认信息、关键证据可信度分层、资格/薪资/市场边界和报告适用范围。关键证据可信度分层只能来自 `source_register.critical_evidence_status`，必须使用客户可读表述，不展示内部枚举或 JSON 键名。不得重复方向建议或泄露“顾问补充”“AI 推测”“内部记录”等内部表述。

结尾固定表达：

> 本报告基于你提供的简历、补充信息及已确认的咨询内容生成，用于帮助你理解当前求职竞争力、方向选择和准备重点。报告中的岗位、薪资、资格和时间窗口判断属于方向参考，不构成录用、薪资、编制、签证、身份或其他结果承诺。

## 5. 跨章节去重与一致性

1. 01 只摘要；02 只放事实和边界；03 只做对标；04 完整展示优势；05 展示差距；06 选择方向；07 准备主方向；08 路径、薪资和行动；09 依据与边界。
2. 同一事实只在一个章节完整展开，同一数字只完整出现一次。
3. 01、06、07 不得原句重复同一推荐理由；03、05、07 不得完整展开同一差距；04、07 不得完整叙述同一经历。
4. 生成后检查重复句和高相似段落；出现重复时保留在章节所有权位置。
5. 检查已确认目标、已有经历、主攻名称、方向类别、招聘阶段、时间限制和待确认状态是否一致。

## 7. 客户语言与禁止表达

正文默认使用“你”，避免“学生”“候选人”“客户”“该客户”等第三人称。不得展示匿名编号、电话、邮箱、住址、内部路径、Skill/Renderer 名称、JSON/YAML 键名或销售黑话。

对敏感经历使用“客观事实＋专业解释＋下一步可行路径”。禁止使用失败、背景弱、机会渺茫、必须放弃等压迫性表述；禁止保证 Offer、内推、录用、薪资、签证、身份、工作许可、移民、具体岗位可投或渠道结果。

客户正文不得把顾问确认纪要、顾问总结或客户自述写成经历真实性已核实。默认禁止自由文本出现“顾问确认其经历真实”“已核实”“已验证”“已证实”等验证性措辞。

## 8. Renderer 集成边界

Renderer 入口必须按运行模式解析：repository 模式使用 `report_renderer/render_report.py`，Plugin 模式由 `scripts/renderer_adapter.py` 调度 `assets/report_renderer/render_report.py`。其确定性调用接口、输入输出和失败边界见 `renderer_v3_integration_contract.md`。Renderer 只渲染已生成的 V3 数据，不得通过修改 Schema 或实现来强行兼容旧字段。
