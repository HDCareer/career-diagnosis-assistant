# SkillⅠ v3.0｜咨询后行动清单规范

## 1. 定位

`post_consultation_action_checklist.md` 是咨询后最终报告的配套执行清单。它不能基于会前诊断初版、逐字稿、顾问总结或内部变更记录直接生成；0.3.0 起由当前运行模式的 `content_materializer.py` 从 `final_customer_report_data.json` 中的 `priority_action_scaffolds`、`consultant_recommended_actions` 和 `jointly_agreed_actions` 确定性物化。repository 模式使用 `workflow/content_materializer.py`，Plugin 模式使用 `scripts/content_materializer.py`。

它不是第二份完整报告、岗位投递计划、销售话术、家长沟通方案或结果承诺。默认保持轻量；核心价值是把最终报告中的高优先级动作转成“今天可以开始”的执行脚手架。如为完整表达必填行动表可略超一页，但不得扩展为后续服务方案。

## 2. 触发条件

必须同时具备：

1. `final_customer_report_data.json`。
2. `final_customer_report.md`。
3. `consultation_confirmation_status: confirmed` 的已归一化咨询纪要。
4. 已生成的 `confirmed_consultation_snapshot`。
5. 已生成的 `consultation_change_log.md`。

如果只有会前初版、原始简历、逐字稿、`draft` 咨询纪要或未整理的咨询材料，不生成行动清单。

生成咨询后行动清单前，必须确认最终报告数据、确定性物化的最终报告正文、已确认的咨询纪要和内部变更记录均已存在。

行动清单的客户内容只允许从 `final_customer_report_data.json` 和与其一致的 `final_customer_report.md` 中提炼。已确认咨询纪要和 `consultation_change_log.md` 只用于一致性校验、确认信息来源和防止遗漏，不得绕过最终报告直接新增行动、方向或结论。

若最终 JSON 与最终 Markdown 不一致，必须先修正最终报告，不能直接生成行动清单。

## 3. 输出文件与固定结构

文件名称固定为：

```text

```

```text

```

## 4. 生成规则

1. 行动清单的客户内容只允许从 `final_customer_report_data.json` 和与其一致的 `final_customer_report.md` 中提炼。
2. 已确认咨询纪要和 `consultation_change_log.md` 只用于一致性校验、确认信息来源和防止遗漏，不得绕过最终报告直接新增行动、方向或结论。
3. “最终方向定案”只使用最终报告的主攻方向和相邻备选；不得重新引入会前已经被咨询否定、最终报告未采纳或变更记录已删除的方向。
4. “仍需确认的边界”只记录最终报告中的剩余未知，且必须从 `source_register.unresolved_questions` 确定性投影；不得重复已在咨询中解决的内容，也不得新增最终 JSON 中没有来源元数据的问题。
5. 主攻、相邻备选、行动路线和重新评估信号必须与最终报告一致。
6. 行动脚手架为 0—3 项，按依赖顺序排列；不得为了凑数强行生成。
7. 有行动脚手架时，每项必须填写行动名称、为什么现在做、依赖关系、前 15 分钟、内容框架、最小可交付成果、预估投入、完成检查和常见错误；其中“前 15 分钟”和“最小可交付成果”是客户执行转化的关键字段，不能写空泛建议。没有高难度行动时保留空数组并物化为“当前无需要脚手架化的高难度行动”。
8. 最小可交付成果必须是可查看的成果，例如证据表、一版简历、STAR 提纲、岗位关键词表、作品补强底稿、投递记录或复盘记录；不得写空泛的“提升竞争力”。
9. 预估投入可使用“15 分钟启动＋2 小时整理”“第 1 周内”等相对表达，不伪造外部招聘截止日期。
10. “顾问建议但尚未确认的行动”和“双方共同确认的优先行动”必须分开；顾问建议不得冒充共同确认。
11. “方向重新评估信号”只写方向相关反馈、资格变化或边界变化；不以焦虑或无关指标触发调整。

默认依赖顺序为：

1. 核实事实和证据。
2. 建立目标岗位能力要求。
3. 重构简历。
4. 补作品或材料。
5. 进入投递验证。

旧 V3 的“未来 30 天优先行动”五列表可继续用于历史兼容渲染；新生成清单必须使用“优先行动脚手架”。

## 5. 禁止内容

不得：

1. 设置负责人。
2. 输出完整后端投递计划、每日投递数量或具体实时岗位链接。
3. 承诺 Offer、内推、录用、薪资、签证、身份或渠道结果。
4. 展示价格、报名、二维码、促销、购买建议或焦虑制造。
5. 把阶段性专业支持、陪跑选择或联系顾问写成优先动作、预期产出或完成标志。
6. 把客户主动排除方向写成“诊断性暂不建议”或重新纳入行动项。

## 6. 与 SkillⅡ 的边界

SkillⅠ 只输出最终报告及本行动清单。销售复盘、家长沟通、三方会议设计和成交路径设计属于 SkillⅡ 的范围，只有用户明确要求时才另行处理。
